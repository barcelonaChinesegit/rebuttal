## 一、文件在哪里

都在 `03_Judge一致性标注/` 文件夹：

| 文件 | 给谁 | 用途 |

| `专家A标注表.xlsx` | 发给同学 A | 2,000 条待标注题目 |

## 二、两个表格怎么用（三步）

### 第 1 步：发表格

- 把 `专家A标注表.xlsx` 发给同学 A，`专家B标注表.xlsx` 发给同学 B，同时把本文第三节“标注规则”发给他们（表格里也有一个“标注说明”工作表，内容相同）。
- 提醒两人：**各自独立完成，标注期间不要讨论，也不要看模型或 Judge 的结果**。

### 第 2 步：同学标注

用 Excel（或 WPS）打开后，“标注”工作表有 8 列：

| 列 | 内容 | 是否需要填写 |
|---|---|---|
| 编号 | A0001–A2000，用来和答案键对应 | 不要改 |
| 任务 | 普通题 / 推理题 / 多文档题 / 不可回答题 | 不要改 |
| 学科 | 题目所属学科 | 不要改 |
| 题目 | 问题原文（英文） | 不要改 |
| 参考答案 | 人工标注的标准答案 | 不要改 |
| 模型答案 | 某个模型给出的答案 | 不要改 |
| **标注** | 黄色列，点单元格右侧的下拉箭头，选 **正确 / 部分正确 / 错误** | **必填** |
| 备注 | 拿不准时写原因 | 选填 |

- 只需要看“题目、参考答案、模型答案”三列做判断，不需要打开 PDF。
- 表头已冻结、可筛选；可以分几次完成，每次保存即可。
- 每条约 20–30 秒，2,000 条约 11–17 小时/人。
- **不要改文件名、不要删行、不要调整列的顺序**，否则脚本读不出来。

### 第 3 步：收回表格、出结果

把两人交回的表格放回 `03_Judge一致性标注/`（覆盖原文件，文件名保持不变），然后运行：

```bash
python3 代码/judge_audit_analysis.py 03_Judge一致性标注/判定答案键_勿外发.csv 03_Judge一致性标注/专家A标注表.xlsx 03_Judge一致性标注/专家B标注表.xlsx 03_Judge一致性标注/一致性结果
```

`03_Judge一致性标注/一致性结果.md` 会输出第五节的全部表格。如果有漏标或填错的行，脚本会列出编号，补上后再运行一次即可。

## 三、标注规则（发给两位同学）

判断“模型答案”与“参考答案”在**这道题要求的内容上**是否语义一致，在“标注”列选择：

- **正确**：题目要求的事实、数值、单位、条件、比较方向全部正确。表述不同但含义相同也算正确（如 `0.5` 与 `50%`、`\alpha` 与 `α`、同义改写）；答案简短但已经充分，也算正确。
- **部分正确**：答对了题目要求的一部分，但缺少某个要求的组成部分（例如问两个数值只答对一个），且没有实质性错误。
- **错误**：数值、符号、单位、方向错误；与参考答案实质矛盾；答非所问；答案为空。
- **不可回答题**（参考答案为 `Unanswerable`）：模型明确表示无法根据文档回答才算正确，给出任何具体答案都算错误。
- 参考答案里有、但题目没有要求的附带细节，模型没写不扣分。
- 拿不准时在“备注”列写原因，但“标注”列必须三选一，不能留空。

> 计分时只有“正确”得分，所以主分析把“部分正确”和“错误”合并，按“正确 vs. 不正确”二分类计算一致性（与论文准确率的计分方式一致），三分类一致性作为补充。

## 四、两个系数是什么意思

### Spearman 相关系数（斯皮尔曼，ρ）——看“排名”是否一致

- 做法：把 11 个模型分别按“专家 A 打分的准确率”“专家 B 打分的准确率”“Judge 打分的准确率”各排一次名次，再比较两种排名有多接近。
- 取值 −1 到 1：**1 表示两种排名完全相同**，0 表示没有关系，−1 表示完全相反。一般 0.8 以上就算高度一致。
- 在这里回答的问题是：**用 Judge 打分和用专家打分，得出的“哪个模型更强”的结论是否一样**。这是基准评测最关心的。
- 表 C 里还有一个 **Kendall τ-b**（肯德尔），含义类似，是看任意两个模型的先后顺序有多少对一致，数值通常比 Spearman 略低。
- 注意：这 11 个模型的准确率差距很大（15.6%–81.0%），排名很容易判断，所以 Spearman 通常会很高，最终数值以实际结果为准。

### Cohen's κ（科恩卡帕）——看“每一道题”的判定是否一致

- 做法：逐题比较两个判定者（例如专家 A 和 Judge）是否给出相同的结论。
- 为什么不直接用“一致率”：假如一半题目是对的，两个人即使随便猜，也有约 50% 的一致率。κ 会扣除这部分“碰巧一致”，只衡量超出偶然的一致程度：
  κ = （实际一致率 − 偶然一致率）÷（1 − 偶然一致率）
- 取值通常在 0 到 1 之间，常用的解读标准（Landis & Koch, 1977）：

| κ | 一致程度 |
|---|---|
| 0.81–1.00 | 几乎完全一致 |
| 0.61–0.80 | 高度一致 |
| 0.41–0.60 | 中等一致 |
| 0.21–0.40 | 一般 |
| ≤ 0.20 | 很弱 |

- 参考：M3SciQA 的 GPT-4 Judge 与专家的三分类κ为0.520（200条回答）。MMLongBench-Doc 的0.42来自数据构建交叉核验，不能当作同一种Judge验证指标横比。
- 审稿人关心的结论是：**“专家 vs. Judge”的 κ 是否和“专家 vs. 专家”的 κ 差不多**。数值接近只能作描述性比较；还需考虑不确定性、评分边际分布及预先定义的容许差，不能直接推出Judge与人等效。
